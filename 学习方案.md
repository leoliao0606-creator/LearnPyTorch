<a id="starting-point"></a>
## 1. Starting Point and Goals

Your current background fits a path with a clear main line, moderate foundation repair, and dense hands-on practice:

- you already know Python syntax, core data types, and basic OOP
- you do not need to restart Python from zero
- your main weak spots are `NumPy`, `Pandas`, and `sklearn`
- you want a combination of concepts, code, and exercises, and `Jupyter Notebook` is a strong primary medium for that

The goal of this roadmap is not to "see many concepts." The goal is to make you able to:

1. write common PyTorch training flows independently
2. read and modify basic deep-learning code written by other people
3. complete an end-to-end project from data processing to training, evaluation, and model saving
4. debug common issues such as shape mismatch, dtype mismatch, gradient problems, overfitting, and data leakage

<a id="overall-strategy"></a>
## 2. Overall Strategy

### 2.1 Main Learning Path

Use this sequence:

**Foundations -> PyTorch Core -> Task Practice -> Engineering and Debugging -> Capstone Projects**

Key tradeoffs:

- do not run a separate full Python review course
- do not try to learn every corner of `Pandas` and `sklearn`
- focus only on the minimum useful core that directly supports PyTorch learning and projects

### 2.2 Learning Medium

Use notebooks as the main learning surface, but not the only one:

- `notebooks/`: explanations, examples, inline practice, and experiments
- `.py` files: extracted reusable code
- `projects/`: structured stage projects and capstones
- `notes/`: distilled understanding, mistakes, and review material

### 2.3 Learning Principles

1. Use first, theory second. Run the code, understand inputs and outputs, then go back for formulas and principles.
2. Touch every topic with code. Reading alone is not enough.
3. Every phase must produce artifacts. Keep notebooks, exercises, experiment records, and small projects.
4. Treat debugging as part of the curriculum. A large part of deep-learning growth comes from fixing failures.

One important convention:

- notebook exercises are the primary practice stream
- `exercises/` is for second-pass drills, review, and standalone submission-style practice

<a id="dataset-sources"></a>
## 4. Dataset Sources and Usage Strategy

### 4.1 Built-in Datasets

Start with two built-in sources:

- `sklearn.datasets` for tabular data and small practice datasets such as `iris`, `digits`, and `breast_cancer`
- `torchvision.datasets` for image tasks such as `MNIST`, `FashionMNIST`, and `CIFAR-10`

Why start here:

- low friction
- strong for teaching
- easy to reproduce

### 4.2 Downloaded Datasets

As you move into more realistic projects, gradually add:

- Kaggle datasets
- UCI, OpenML, or public course datasets
- datasets released with competitions, papers, or official benchmarks

Recommended practice:

1. create a subdirectory under `datasets/` for each project
2. keep raw data and processed data separate
3. document the source, download method, and schema in a notebook or `README`

### 4.3 Synthetic or Toy Data

Small synthetic data is extremely useful during the learning phase.

Use it to:

- validate `Dataset` and `DataLoader`
- verify shapes, padding, and masks
- build controlled edge cases
- create tiny debugging scenarios and minimal reproducible examples

### 4.4 Recommended Dataset Progression

1. small built-in datasets
2. synthetic toy data
3. public medium-size datasets
4. full capstone data

<a id="python-refresh"></a>
## 6. Python Topics to Refresh

You do not need a full Python reboot, but you do need these topics because they appear constantly in PyTorch work:

- function arguments: defaults, keyword-only parameters, `*args`, `**kwargs`
- OOP: classes, inheritance, `super()`, instance attributes, and methods
- special methods: `__len__`, `__getitem__`, and simple containers
- iteration: loops, iterators, enumeration
- file and module organization: imports and clean project structure
- assertions, exceptions, and basic validation
- context managers such as `with`

These topics should be refreshed in context, not isolated into a separate long course.

<a id="phase-roadmap"></a>
## 7. Phase Roadmap

### Phase 0: Minimal Foundations

Focus:

- Python refresh for ML
- `NumPy`
- `Pandas`
- visualization basics
- a minimal `sklearn` pipeline

By the end of this phase, you should be able to:

- clean basic tabular data
- understand train/validation/test splits
- explain simple plots and metrics
- build a small baseline model before touching neural networks

### Phase 1: PyTorch Core Basics

Focus:

- tensors, shape operations, dtypes, and devices
- autograd
- datasets and dataloaders
- `nn.Module`
- losses and optimizers
- the training loop
- saving, loading, and inference

By the end of this phase, you should be able to:

- write a basic training loop without looking things up every line
- explain data flow from `Dataset` to `DataLoader` to model to loss
- debug common shape and gradient issues
- save and restore a trained model

### Phase 2: Computer Vision Track

Focus:

- image data and transforms
- CNN basics
- CNN classification
- regularization and schedulers
- transfer learning
- a small image capstone

By the end of this phase, you should be able to:

- read basic CNN code
- compute output sizes through convolution stacks
- recognize overfitting and apply fixes
- use transfer learning in a controlled way

### Phase 3: Sequence Modeling and Intro NLP

Focus:

- sequence basics
- LSTM
- attention
- Transformer encoder basics
- optional pretrained text models
- a text capstone

By the end of this phase, you should at least be able to:

- reason about sequence shapes
- use embeddings with token ids
- train a simple LSTM classifier
- explain the core difference between recurrent models and attention-based models

### Phase 4: Engineering, Debugging, and Best Practices

Focus:

- project structure
- debugging playbook
- checkpointing and logging
- GPU and efficiency
- result analysis

By the end of this phase, you should be able to:

- turn notebook prototypes into small maintainable projects
- reproduce experiments cleanly
- debug training issues systematically
- write short but useful experiment conclusions

### Phase 5: Capstone Projects

Focus:

- tabular classification capstone
- text classification capstone

Capstone expectations:

- clear problem definition
- explicit data processing steps
- at least one baseline
- at least one improved model
- at least two controlled comparisons
- plots plus written analysis
- a concrete next-step section

<a id="stuck-strategy"></a>
## 11. What to Do When You Are Stuck

Use this sequence:

1. restate the shape, dtype, and device of the main tensors
2. print intermediate outputs
3. reduce the problem to a minimal reproducible example
4. check whether the data pipeline is correct
5. compare against a known-good baseline
6. write down the failure in an error log

Do not let confusion stay in your head as vague frustration. Turn it into a concrete record.

<a id="mastery-criteria"></a>
## 12. How to Tell Whether You Really Learned It

You have probably learned a topic when you can do all three:

1. explain the idea in your own words
2. write or modify the code without line-by-line copying
3. debug a broken version of the same idea

Recognition is weaker than recall, and recall is weaker than independent use.

## 13. Timeline Overview

A reasonable pace is:

- Phase 0: 1 to 2 weeks
- Phase 1: 2 to 3 weeks
- Phase 2: 2 to 3 weeks
- Phase 3: 2 to 4 weeks
- Phase 4: 1 to 2 weeks
- Phase 5: 2 to 4 weeks

Adjust the schedule based on depth, not speed. It is better to finish fewer topics with real control than to skim everything.

<a id="final-advice"></a>
## 14. Final Execution Advice

Use the repository as a working lab, not as a passive reading archive.

- run code
- write predictions before execution
- keep notes
- log mistakes
- compare baselines against stronger models
- revisit old notebooks after a gap

If you keep the cycle of learn -> code -> fail -> debug -> summarize, this repository can carry you from fundamentals to real small projects.
